# 提示词写作律（dnd5e 卡 · 用户指令全录 2026-09-19）

本文档 = 用户在提示词方面全部指令的归并存档——三份提示词（systemPrompt/postPrompt/maintenancePrompt）的每一处措辞都可回溯到这里的某一条。改提示词前先读此律；与律冲突的措辞即欠账。

## 一 · 身份与感知（提示词写给谁）

1. **systemPrompt 双脸共享**（引擎 registerCardSections 主/尾都调）——措辞必须让每个读者先自判身份；"未得到正式任务指派前，不做那类事"。
2. **尾代理去人格化到底**：不自称任何代理身份（连"簿记代理"都不写）——任务制开篇；也不感知主代理（输入只是 transcript＋任务指令）。
3. **主代理不感知尾代理**：落账是"自动流程"，没有同事人设。
4. **提示词只说 LLM 可见的三样东西**：注入面板、工具 schema、路径参数——服务器目录名（`runtime/`）、文件布局一律不出现（"llm 根本看不到 runtime 字样"）。

## 二 · 内容分工（写什么，不写什么）

5. **systemPrompt 构成**：DM 定位＋世界如何运转＋工具纪律＋流程骨架＋SRD 索引＋高度关注项——"角色定位就是 DND5e DM，啥位置有 SRD 文档可供查询"。
6. **SRD 索引入 systemPrompt**：每类别=简介＋全部条目名（mega 三类折叠为指针）；路径说明相对谁（前缀声明一次省 token）；两级查询（索引→类 INDEX→原文）。
7. **规则效力顺序：本提示明文规则 > SRD 原文 > 记忆**（单人卡适配/时相/DMG 口径等刻意偏差以此合法化）。
8. **SRD 所举即全部**：怪物/法术/物品以语料为完整名册——不自创；需要变体改数值不改名册。
9. **工具内部规则绝不写进提示词**（gain_exp/gain_money 只说"必须调用"）——规则唯一载体=工具实现与其引用的语料。
10. **DM 手艺不写文档**：systemPrompt 点睛即可，引用口径注明出处（冒险日=DMG 非 SRD）。
11. **末行自演算小结**："一句提示词的事"——叙事段量复述即自校验（"整体回复的数据都会更加有逻辑和准确，因为相当于自我演算"）。

## 三 · 注入面（postPrompt 形态）

12. **语义面板化**：输出面固定格式全写在 postPrompt——【玩家面板】{{get_player_state()}} 等具名脚本分节；**"回合快照"概念废除**，要"更语义明确的谁的面板"。
13. **注入集**：玩家＋同伴（role:companion 常驻）＋**叙事点名 NPC**（脚本扫最近一轮主 agent 正文∪玩家本轮文本，点名即在场——零名单可维护，误注入只多不少方向安全）完整面板；**没人提的 NPC 不注入**；**【人物志】=全部 character 逐条一句话简介**（人际关系简图，注入器自动扫描零维护）。
14. **暂时全量原文注入**（不摘要）——摘要层挂账为量测后优化项。
15. 变化数字的呈现分工：正文陈述事实与数值（落账的来源），HUD 变化日志呈现结果——正文不复述已上屏的账。

## 四 · 纪律条款（行为规则）

16. **主面工具全员 `context` 必填**（绑剧情反作弊："骰值只裁定此刻成败，不得覆盖走向"）——叙事段与结算收尾皆然。
17. **禁止心算清单**：一切 d20/伤害/豁免/价格/找零/XP 走工具；agent 只做判断（检定选择/DC 档/优劣势/掩体/特征骰条件/即死累计）。
18. **买之前先判断是否买得起**（对照玩家面板钱包）；gain_money 忠实落账不拒绝，负余额=回执警示。
19. **工具拒绝＝世界事实**：改叙或给玩家新选项，不硬圆。
20. **战前先铺场**：敌意显现先叙述场景与选项，不掷先攻不建战斗面板；接战才开战。
21. **战斗节时序**（原 combat.json,2026-09-20 并入 state.md）：无战=「（无战斗）」占位——战斗生命周期严格夹在「先攻掷出→战毕当回合」,md 行比 JSON 模板更抗写歪（巨狼案教训）。
22. **一条玩家消息＝一轮**（DM 单回复按先攻序推演完所有单位；act_index 仅断点）。
23. **工具覆盖的行为必须调用工具**；覆盖不了的 agent 直做——**无二期**。
24. **意图优先**：玩家说意图，DM 找机制；第一回答永远是"好，你可以试"。
25. **roll 回执语义自述**：命中判定/伤害判定分行标明——"要不知道这个数是啥"即不合格。

## 五 · 方法论判词（工具面演化的刀）

26. **工具越少越好；输入输出语义明确，实现复杂无所谓**——语义明确的 I/O 就能被 LLM 用好。
27. **总是一起调才合并；输入不同/逻辑复杂就分开**（mega-roll 的分裂依据）。
28. **计算器定律**：主面工具零写盘纯函数；写盘归转录任务与前端通道。
29. **无状态律**：读回合内不变量、输出增量/判定；快变量累计=DM 单步叙述+尾代直编。
30. **级联/直编二分**：只有多步级联配得上工具（gain_exp/gain_money）；其余=单步四则+查表的直接编辑，规则查语料不复制进工具。
31. 中间状态靠参数传递（回执中继），不靠磁盘传话（rolls.log 消亡理由）。

## 六 · 同源原则（历次被推翻的共性）

每次提示词/工具面被修正，病灶都是同一种：**让 LLM 承担了它看不见或不必看见的东西**——看不见的目录名、不必背的规则表、不该感知的同事、不该拒绝的余额。修正方向永远一致：**LLM 只处理它此刻的任务与它眼前的文本；一切机制沉到工具与语料里。**
