## 4 · 玩家工位操作注入（2026-09-22 用户定案，已落地；同日二次定案去栏目化）

**动因**：玩家点选是前端机械道——不进 transcript、不进快照、【上回合变化】是尾代所有权节；于是 DM 对「玩家做了什么」零信号（面板只有结果现值，无行为事件）。用户拍板：被操作的事实在面板、玩家行为的事件流需要独立入桌——**两者不矛盾，事件行只表达「做了什么·产生什么效果」**。二次定案（用户）：**自然语句、无栏目、置于面板之前**。

**契约**：

- **记账**：`front_commit.mjs` 每笔**成功**操作（asi/spells/prepare）追加一行 `.front-ops.jsonl`；被拒操作不进账。效果串由机械层如实生成（旧→新绝对值、CON 追溯 HP），LLM 不参与措辞。
- **注入**：`preset/scripts/get_player_ops.mjs` 占位符 `{{get_player_ops()}}` 挂 postPrompt **首行**（【玩家面板】之前）——事件以自然语句逐行平铺（「玩家分配了属性点：…」），**无栏目无标题**；末行按需带「还剩 N 点属性点未分配」——**现读** player.json 的 pending（ASI 档×2），与面板同源不生产第二真相。**无操作＝完全零输出**（用户要求留空）。
- **时态无关**：行存最近 5 条 roll-off、跨回合驻留，不设消费/清除仪式（避免在渲染路径做破坏性副作用）；DM 读作「玩家工位上的行为」，既可顺势叙事确认也可忽略。
- **所有权**：`.front-ops.jsonl` 是前端机械道私账——tail 无教案触及、`{{get_changes()}}` 的「上回合变化」节照旧只从 transcript 重写，两条通道各司其职。

**注入原文样例**（分了档一、档二未分时 DM 实收开头）：

```
玩家分配了属性点：力量 +2（16→18）。
还剩 2 点属性点未分配。

【玩家面板】
{ "str": 18, …, "pending": [ "LV6·ASI 点选" ] }
```

**验证**：shell 四场景（分一档剩一档=事件+剩余行／全分完=仅事件／无日志=0 字节／档案缺=略剩余）＋6 笔 trim 至 5 行 roll-off／拒绝不落账；浏览器 e2e 复跑 12/12 PASS 且新措辞两档操作经桥如实落日志；engine 套件 131 全绿。

- **风险**：低。纯公式修正——升级时点（gain_exp 用现调整值逐级加）与默认均值路径不受影响。
