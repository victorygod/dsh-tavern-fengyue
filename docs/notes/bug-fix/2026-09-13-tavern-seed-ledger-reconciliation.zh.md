# Agent Note: Tavern 种子账本对账（fork 子会话）

Status: implemented

[English](2026-09-13-tavern-seed-ledger-reconciliation.md) | 中文

## 问题

玩家存档后继续游玩、再点「载入」时，出现两组稳定复现的缺陷。(1) 载入把工作空间换绑到存档点会话的 fork 后，子会话把玩家已被回滚的消息当作自己的第一个回合重跑——模型再答一遍，幽灵回合浮在玩家新输入之上。(2) 载入后玩家发出的第一条消息被执行两次：主代理一次、记账尾代理一次。两者都在真实 `session.v3.jsonl.zstd` 取证中定案：幽灵认领带着客户端的原始 `rpcId`，子会话日志里摆着 inbox 账本的 `agent/inbox/spliced` 入队记录、而配对的注销记录落在种子切点之外。

根因：内核的每种种子切片都可能切断一对账本。`sessionController.fork` 把切点推进到下一个 `turn/start`——存档边界之后排队的消息以"已入队"记录进种子、"已认领"记录留在种子外；尾代理的已完成回合切割对"父会话最后一回合进行中入队、其后才认领"的消息同样切断。子会话的 inbox 投影把半对账本折算成一条它从未合法欠下的待办消息，循环在首次认领时把它排干。

## 决策

引擎在自己的两个"首次认领之前"关口上对账。`repairSeedInbox`（新增 `inbox-repair.ts`）重放种子区账本——逐条镜像 inbox 投影的坐标校验——然后追加持久注销事件（`agent/inbox/spliced` 带 `outcome: 'canceled'`，同 target 内按下标降序）。`load` 以 fork 源的 `livePendingIds` 为保留集调用它：源会话仍真实在途的条目保留（内核"继承真实在途输入"的交接契约不破），源已消费的条目勾销；`composeTailAgent` 不带保留集调用——尾代只管记账，父会话消费自己的队列。own 区送达的内容在构造上不可被触及：尾代理的维护提示词经 `child.followup` 在种子之后进入。

## 备选方案

**改内核种子切法。** 把每个种子的账本对齐到切点时刻的父会话状态（在 `sessionController.fork` 与 fork provider 内）是语义上的家，也能让所有 fork 消费方干净——本次落选因为要动两个核心包、重塑一条被测试钉死的继承契约，而该缺陷在产品里只有 tavern 的存档/载入会踩。它仍是文档记录的长期归宿（`docs/tavern-prototype/load-rebind-debug_zh.md` 三轮定案）；落地时本文两处修复点直接删除。

**在 pre-step 闸门丢弃幽灵。** 闸门可以拦下账本从未配对过的首条认领；落选因为幽灵的持久 user/message、回合事件、转写行在 pre-step 之前已经存在——可见的损害照常出现，只是不再进模型。

**保存时建干净的存档子会话。** 保存瞬间就 fork 一个子会话（其源日志恰好终止于边界——无可切断），载入时直接换绑不再 fork。落选在代价：每次保存（含每个 autosave 回合）多一个 fork 子会话，旧存档还要另配兜底路径；载入时对账免费覆盖所有既有存档。

## 后果

载入与记账从平衡账本起步：无重跑回合、每条消息单次消费、每个子会话日志里留下可审计的注销轨迹。代价是对账以插件身份写入 agent-loop 拥有的事件词汇——机制上由投影 fold 的 fail-loud 坐标校验把关、而非所有权边界——因此 agent-loop 账本规则变化时 `inbox-repair.ts` 必须跟随。REAL 组合测试双向钉死：禁用修复点即可复现被切断账本的重跑；尾代测试钉住父排队消息只跑一次。
