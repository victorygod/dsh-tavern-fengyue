# Agent Note: Tavern request-view wrapping and dual-agent composition

Status: implemented

English | [中文](2026-09-12-tavern-request-view-wrap.zh.md)

## Problem

Four real defects shipped with the tavern engine, all invisible to the unit suites because they only appear in a real composition: (1) the main agent's first turn assembled an empty card (the prerender cache was warmed at session creation, before any card import, and the only refresh sat in the `agent/pre-step` gate after assembly); (2) the session controller mounted the configured default agent preset — thirty product tools and a coding persona entered the tavern world, the tail fork inherited the same surface, and the tail's write trio never registered; (3) the browser transcript read the `eventSource` entry object as the event itself, so nothing a user typed ever rendered; (4) `tailRunning` never crossed the wire (`state` projection omitted it), so the bookkeeping banner, send gate, and tail row could never appear. Separately, prefix/post prompt semantics were settled as request-level wrapping — wrap ONLY the current turn's user message, keep history raw — which the runtime-context snapshot mechanism cannot express at all.

## Decision

**A generic, tavern-blind request-view extension point.** `agent/request-messages` (declared in `packages/core/agent/src/runtime-types.ts`, dispatched in `packages/core/agent-loop/src/agent.ts` `buildRequest` after `deriveMessages()`) is an awaited scoped waterfall over the REQUEST VIEW: the log is never touched; `payload.current` carries the durable `(seq, message)` pairs appended for THIS step's accepted input, so a listener identifies the in-flight message by identity, not position. The reconstruction invariant (the dispatch JSDoc owns it): every returned message must be reconstructable from durable state, so externally derived text is materialized as durable snapshot events BEFORE the request that uses it. The fused dispatcher injects `agent`, so the loop passes the rest — a detail the scope invariant spec caught the moment the event appeared.

**Tavern's wrap: materialize-then-rewrite.** Rendering moved INTO the `system-prompt/assemble` waterfall listener (`packages/extensions/tavern/src/prompting.ts`): raw-file section providers stay synchronous, the listener resolves `{{script}}` and probes `-h` tool briefs (mtime cache kept), then rewrites the assembly in place — the prerender cache class is gone, so first-turn emptiness and the stale-by-one-turn gate ordering both dissolve. The listener reports the rendered prefix/post pair to the engine, which appends ONE durable `tavern:wrap` snapshot user message whenever the pair CHANGES (cleared marker when both go empty — same supersedes semantics as runtime context). A scoped `agent/request-messages` listener then rewrites ONLY the current claimed user message to `prefix\ntext\tpost` in the request view. Result: `[s, u1, a1, …, p+uN+p, aN]`, history raw forever, UI raw forever, every past request rebuildable from the log.

**No product tools in the world.** Tavern sessions are created through `session.create({ agentPreset: 'none' })` — an explicit no-preset path added to `packages/api/session-controller/src/agent.ts` (`'none'` mounts nothing, adopted resumes stay `none` instead of falling back to the configured default). Both agents additionally `tools.restrict({ allow: [] })` (the restriction governs inherited layers; the agent's own scoped registrations survive) and `systemPrompt.suppressRuntimeContext()`, which removes the policy prose from the snapshot without touching enforcement. The main agent's request tools are exactly `executeTools / runtimeRead / runtimeGrep`; the tail's are exactly the fixed five.

**The card is the whole system prompt.** Three global product sections — `harness:identity`, `harness:source` (the checkout-location line), and `app:web-surface` (the Web-GUI orientation) — register on the root scope and would ride every tavern assembly. Each tavern agent scope shadows all three with same-name EMPTY sections (documented scoped shadowing), so the assembled system is the card text plus the `-h` tool brief and nothing else; other sessions in the process are unaffected. The composition test pins the request's system to the card text byte-exactly, so a renamed product section fails loudly instead of silently rejoining the prompt.

**The tail's seed keeps its wrap.** The retention rule: the wrapped `p+uN+p` view lives only while that message is the CURRENT one — the main agent de-wraps it the moment a new player input is claimed. But the tail fork reads the JUST-finished turn, so its seed's last player-sourced user message RETAINS the wrapped view, rebuilt from the parent's durable wrap snapshot pair (reconstructable, same-source); the tail's own maintenance message never wraps. Verified by the composition test: the tail request's user texts contain `prefix+text+post` for the accounted turn and the maintenance text last.

**清空 rebinds the workspace instead of rewriting history.** Logs are append-only, so "chat history cleared" is delivered by binding the workspace to a FRESH session (`agentPreset: 'none'`, same cwd): the player sees an empty history and the opening page, `runtime/` re-seeds from `preset/setup/`, `savings/` stay, and the old session's durable log remains archived unbound. `engine.reset` returns the fresh session id (api `reset` projects it; the client opens it and drops the old sidebar last-line cache). The composition test drives a post-reset turn: no pre-reset text in the fresh request view, identical card system, fresh tail bookkeeping, third autosave.

**The tail is a peer of the main agent, not a persona.** `turn/end` with `reason.kind === 'completed'` alone schedules the fork (error and aborted turns produce no bookkeeping). The fork request carries no persona; the maintenance prompt IS the fork's first user message under a one-line engine preamble. `agent/created` composes the child with the SAME card sections as the main agent (the fork seed already carries the parent's system history — systems are same-source), the five `runtime*` tools, and the same restrictions. The parent lookup reads `agent.session.header.parentSession` directly (the old session-store lookup was how the write trio went missing).

**The wire tells the truth now.** `tailRunning` crossed every layer (engine state → api projection → client shim, with client fakes rebuilt against the SERVER projection — the standing lesson). The transcript unwraps `entry.event` (skipping `transient` rows), renders user bubbles only for `source.kind === 'user'` append surfaces, drives the typing indicator from the session snapshot's `running` bit, and surfaces `promptError`/`openError` as rows. The sidebar cover reads `readAsset(sessionId, …)` — workspace covers live in the workspace, not the library. And the modules server now WARNS at boot when a served `lib/client.js` is older than its package sources: the original "all buttons dead" report was a stale silent bundle, not current code.

**Mock LLM logs read like a transcript.** `dsh-llm-mock-server` defaults to `--log-format pretty`: one summary line per request (behavior/model/stream/message count/tool count) followed by the full model-visible context — system text, every message, tool names; one outcome line per result. `--log-format jsonl` keeps the byte-for-byte machine shape for pipes/jq, and the tavern testing doc teaches it that way.

## Alternatives considered

**Three durable messages per turn (`p, uN, p`).** Rejected: history accumulates wrap rows every turn and the prefix sits before the message only by event order, not by composition.

**Runtime-context snapshots for prefix/post (the shipped mechanism).** Rejected per the settled semantics: they ride a snapshot placed after the user message alongside product policy prose, cannot wrap the current message, and deduplicate against unrelated changes.

**A preset row disabling product tools profile-wide.** Rejected: it is host-wide, not per-agent; `restrict({ allow: [] })` at the agent scope states the same invariant in the registry's own vocabulary and survives a user patch re-enabling rows.

**The tail as `delegation` persona.** Rejected: the delegation context describes permission scoping to a subagent; the tail's job is a concrete user instruction, and its system already matches the main agent's.

## Consequences

New agent-subject events require regenerating `packages/core/scope/src/scoped-events.generated.ts` (`pnpm run gen-scoped-events`); a miss turns the scope invariant suite red. The REAL-composition test (`packages/extensions/tavern/tests/loader-composition.spec.ts`) is the coverage gate for composition semantics — tool faces, wrap shape, same-source systems, completed-only tail scheduling, autosave, wrap snapshot count, runtime-tool writes — with a thin `sessionController` stub forwarding to the real `agents` factory (the BFF assembly layer's own coverage stays with `packages/api/session-controller`). Any plugin may now rewrite the model-visible request view per step through `agent/request-messages`; the loop logs nothing for the dispatch itself, so externally derived text must be materialized as durable snapshot events first or the reconstruction invariant breaks — pinned by tests and reviews, not loop enforcement. Tavern resumes of pre-fix sessions legitimately reassemble their old preset surface (durable history drives both `system/message` and the stored `agentPreset`), so verification of the new semantics needs fresh sessions. The session controller accepts the literal `'none'` as an explicit no-preset request typed as plain `string` — a documented convention, not a brand. A keyless recorded-session snapshot for the changed model-visible surface remains open; the composition test's durable assertions cover the same events this round.
