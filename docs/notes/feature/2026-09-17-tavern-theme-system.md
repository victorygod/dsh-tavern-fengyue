# Agent Note: Tavern theme system (three built-ins, consent-free, header select)

Status: implemented

English | [中文](2026-09-17-tavern-theme-system.zh.md)

Date: 2026-09-17 · Surface: `packages/client/ui-tavern` (zero engine changes)

## Problem

The tavern page's colors and fonts were baked in: tokenization was half-done — `--t-*`/`--tv-*` (two families, same values, different prefixes) were declared on `.app`/`.root` while a hundred-plus literals lived outside them (white cards, ink buttons, the user-bubble trio, the danger family, the warm-brown shadow family…), a half-token state no theming mechanism could reskin as a whole. A card's `preset/ui/` pack prompted a `window.confirm` on first enable, and the settings page offered no place to pick a theme.

## Decision

**One injection point, one token family, one selection seat.**

- **`themes.ts` is the only writer of `#tavern-theme`**: one stylesheet landing on the new stable root hook `.tavern-root` (hung beside `css.app` on the TavernApp root div), content = the selected built-in's token rule + (under the card choice) the card's `theme.css` block. Three built-ins: parchment (the `.app` values verbatim), dsw light / dsw dark (each `ui-theme/src/styles/design-platform.css` alias resolved to literals — the `bg/bg-deep/surface-2/surface/card` five layers, two border steps, four fg steps, the full accent set, ok/danger trios, the bubble trio, veil/scrim, and the font stack serif→DSH sans). Alpha families split into `--t-gold-rgb / --t-danger-rgb / --t-shadow-rgb` triplet tokens; use sites write `rgba(var(--t-x-rgb), α)`, preserving every original per-step alpha.
- **Both module CSS files fully de-literaled** (single `--t-*` family, `--tv-*` folded in): roughly 20 white surfaces, 3 bubble values, 6 send/primary gradient stops, 8 danger values, 15 shadows, assorted golds; the library cover tint gradients and their white veils/text are **card artwork** and stay literal by design (README Known Limitations records this). The `SF Mono…` font literals fold into `var(--t-mono)`.
- **The consent dialog retires**: installing a card already grants host-level trust (its scripts/tools are host-side bash — the `card-presentation` trust model), the `ui.consent` key is deleted, and the pack applies outright. `card-ui.ts` no longer injects theme.css — it returns it as `handle.themeCss` for themes.ts to fold into the sheet; `chat.css` (`.tavern-stage` prefixing), `layout.json`, and `mount(tavern)` are unchanged.
- **Override semantics**: the theme seat is the always-mounted top-right header select (first in `headActions`, chat and library pages alike — it started the day on the settings files tab and moved the same day: the settings page is a modal two hops away); four options — card theme (if any) / parchment / DSW light / DSW dark, persisted at `tavern.ui.theme` (plain localStorage, the `tavern.lastLines` pattern); a built-in choice replaces the card's theme outright (its css never enters the sheet); the card choice appends the card css behind the parchment base (a card may override tokens on `.tavern-root` — under the old injection model `:root` could never beat the module class, so card themes can now genuinely retheme the whole page for the first time).
- **The sheet lives on the always-mounted body**: `TavernChatView` mounts conditionally (unmounted on the library/settings modal), so the writer sits in `TavernAppBody` — a `useLayoutEffect` lands the sheet before first paint to avoid a default-color flash, and only the unmount path calls `clearTheme`; the card-side `themeCss` rides the single reporting port `onCardTheme`. Selecting applies live, no reload.

## Alternatives considered

- **One full CSS bundle per theme** (the literal reading of "css packaged as a set"): rejected — three thousand-line copies maintained in lockstep; the token base with full de-literalization covers the same dimensions (fonts included) while card authors override tokens instead of whole sheets.
- **Live `var(--dsw-*)` references for the dsw themes**: rejected — live references auto-flip with `body[data-ds-dark-theme]`, which contradicts an explicit dsw-light/dsw-dark choice; and jsdom has no body tokens to resolve. One-time resolution to literals keeps a theme dead data.
- **Keep consent, move it to a per-card settings switch** (the earlier pending item): overruled by explicit instruction — no dialog, apply outright; the trust model was already front-loaded, and the honest boundaries (Known Limitations, covers-as-artwork) are documented.
- **The sheet writer in `TavernChatView`**: rejected — conditional mounting removes the tokens on the library page and settings modal, leaving the page unstyled; a three-line reporting port buys permanent correctness.

## Consequences

`tests/themes.client.spec.ts` (jsdom): the three token sheets, both card semantics (append order, replacement exclusion), single-sheet replacement, clearing, localStorage roundtrip and garbage fallback. A header-select case in `tavern-app.client.spec.tsx`: the four locale-owned options, the sheet swapping to `--t-bg: rgb(21, 21, 23)` after a change, and `dsw-dark` persisted; `tavern-view.client.spec.tsx` pins the workspace surface as theme-row-free. The ui-tavern suite is 122/122; `tsc -p` is clean. Docs: bilingual README gains the `card-ui.ts`/`themes.ts` entries plus two theme limitations; `card-presentation_zh.md` flips five consent claims and registers `.tavern-root` in the hook contract.

Second batch the same day (user walk-through feedback): **message foot row** — the timestamp used to hang below the bubble via `position:absolute; bottom:-17px`, misaligned with the fixed 20px actions row (the user asked why messages were so tall and why time and buttons were not on one row); now `.msgFoot` carries both in one row (right-aligned `[time][copy/↻]` for user lines, left-aligned `[copy/↻][time]` for narrative, `margin-left:auto` for the error row), with the old `.stamp` positioning and reveal rules moving to the whole foot. **Flow-row clustering** — consecutive think/tool/tail rows tighten to 4px via a sibling negative margin (-12px) and flow↔narrative to 8px (stock's closed-process→answer step), matching Stock's reasoning rhythm; the user asked for the three to read as one block. **The narrative gold tick retires** — `.narrative::before` (a 12×3px gold bar) the user called silly, deleted; its reserve folds back (padding-left 24→8) and the file-header comment drops the gold-tick wording. **Third round (same day, "look at the stock webUI")**: typography moved onto the stock chat ladder — `:global(.tavern-body)` line-height 24px with markdown `<p>` margins pinned to 0/16 (browser defaults stacked before), narrative/bubble line-heights unified at 24px; the think row was rebuilt as the stock `DisclosureRow` primitive with `IconThinkOutline14` (24px row, 13/20 tertiary body, hover chevron, running sweep) — the interim line-height:1 ask was superseded by this reference alignment, and the card's own `preset/ui/chat.css` (1.95 + per-message margin stacking with the column gap) was found overriding the host and trimmed.
