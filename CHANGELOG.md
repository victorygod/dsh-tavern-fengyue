## [Unreleased]

### Added

- **SillyTavern text-macro compatibility batch (`st.mjs` standard script)** — ST macro syntax has no runtime in this project; the importer is the single translation boundary (decision record: `docs/notes/feature/2026-09-25-st-text-macros-getvar.zh.md`). At fold time every text field runs a three-way sorter: runtime-dependent macros become `{{st(...)}}` calls (`user`/`persona` from the `runtime/persona.md` frontmatter `name:`/body, `char` from `preset/meta.json`, plus `time/roll/random/pick/set/get/last/pending` subcommands — one vendored `preset/scripts/st.mjs`, a plain card script with zero engine awareness); static self-references and 1v1 constants bake into literals; the dead end (`{{original}}/{{pipe}}/{{model}}`) is stripped with audit rows. Invariant: after the fold, kernel-facing text carries no bare `{{name}}`; the three-ledger audit (translated/baked/stripped) lands in the import report with originals preserved verbatim in the `st`/`fy` slots. Engine: `renderPlaceholders` now re-scans script stdout one level (world-book content injected through `{{lorebook()}}` stdout resolves its own tokens; survivors are scrubbed with a visible `rescan` failure row — never left verbatim into the kernel's strict interpolation) and the per-render spawn budget rises 8→24 (`packages/engine/src/prompting.ts`). Client: the default opening page resolves the three snapshot keys (`{{st('user')/('persona')/('char')}}`) into the draft before the greeting button fills it; runtime-dependent tokens stay literal in labels by contract (user-surface text is never rendered). `persona.mjs` is retired (`{{persona()}}` calls in existing cards keep working via the script registry).
- **ST-card import hardening (real-corpus-driven)** — `isFengyueCard` now requires `pre_prompt` to co-occur with the fengyue features, so ST community cards carrying a top-level `world_book` no longer get silently hijacked into the fengyue fold; settings/preset exports (named but content-empty) are rejected with a dedicated message instead of folding a hollow card; regex packs (array form and Marinara style) get dedicated refusals. Fengyue world book: `_and_` composite keys translate to a real AND match (`lorebook.mjs` v1.6, `mode: 'and'`), missing/zero `key_region` now means never-triggers (aligned with the fengyue reference implementation), and previously silent drops (`builtInCss`/`bg_image`/`suggested_questions_after_answer`) land as report rows. Nine real cards from the user's corpus verified end to end.
- Root `LICENSE` (MIT), `CHANGELOG.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, and `THIRD_PARTY_NOTICES.md`.
- GitHub issue/PR templates and a cross-platform CI workflow (Ubuntu / macOS / Windows × Node 22 / 24).
- `pnpm lint` (oxlint) with the vendored source snapshots excluded.
- **`tavern.turnError` card face (回合失败通道)** — the host pushes live turn failures to mounted cards, text-identical to the transcript's `.errMsg` row and gated by the reader's `primed` flag: live turns only, remount replays not re-delivered (the transcript history row stays the durable record). Built for cards that hide the transcript — until now a failed turn on the galgame card (转写区恒隐) never reached the player: the composer spun out the 120s watchdog and fell back to input silently. The Furina card renders the fact as a banner in the dialog box (`.gg-err`, stop-button red family): a `waiting`(phase) falls back to input immediately (the watchdog is now the fallback, not the UX), the banner survives until the next success beat (boot/①settle) clears it, and empty-fact beats defer to the watchdog rather than flashing a blank banner. Includes the fast-fail echo latch: a provider that dies faster than the card's ② (snapshot write → file-event pump) can beat the user row to the card; the first ② after such a failure is that failed turn's own echo and no longer enters `waiting` (慢败序 unchanged). Contract tests on both sides (pure-event face + mount-face wiring; five galgame behavior pins) and a dual-phase real-machine driver `scripts/e2e-gal-errorface.mjs` (error / happy). Note for E2E authors: galgame-form drivers cannot use the send-button-shape settle primitive (the composer collapses into the card slot during reading) — the driver settles on transcript text growth and targets `.gg-dock-slot textarea`; hashed CSS-module class names need suffix matching (`[class*="errMsg"]`).
- **Card-script failure diagnostics now reach the screen** — the api layer's structured `value.failure` (reason + exitCode) was dropped by the client `runScript` face, so every script failure everywhere surfaced as an empty string and, on the card pump, the uniform 「数据源未就绪」 after nine retries. The face now throws on `failure` (reason + exit code in the message), the Furina pump folds that into its not-ok envelope instead of swallowing it, and the boot-failure actor prints the concrete reason in the dialog. This is what made the Windows diagnosis below a ten-minute job (note: `docs/notes/feature/2026-09-27-turn-error-face-channel.zh.md`).
- **`scripts/probe-card-script.mjs`** — a cross-platform layer probe for card-script execution: it re-creates the runner contract by direct spawn (never through the host shell/sandbox), checks bare-PATH `node`, runs the runner twice (absolute-path node / PATH node) with cwd = `runtime/`, and prints exit/stdout/stderr per step. It distinguishes "the script ran and produced its own business receipt" (exit ≠ 0 with stdout — stack healthy) from a broken node/runner stack, so a Windows box can self-diagnose whether the host shell layer or the script layer is at fault.

### Changed

- **Engine-owned card spawns declare an explicit full-access sandbox policy (`trustedScriptPolicy`)** — the engine's shell seams (prompt-phase `{{script}}` renders, the frontend pump `tavern.runScript`, and card tools) previously sent no sandbox policy, so the kernel's executor fell back to the session surface (`workspace-write`) — and on hosts without a usable sandbox backend that is an outright refusal, not a fallback. Cards are trusted host code by the card-UI trust model; their spawns now carry `{ mode: 'danger-full-access', workspaceRoot: <root> }` explicitly (the shape the kernel's own error text prescribes), decoupling card functionality from session sandbox mode switches and from backend availability. The card's writable world remains its own `runtime/` under that root (note: `docs/notes/bug-fix/2026-09-27-windows-sandbox-refusal.zh.md`).

- **Upgrade toolchain for the dsh dependency** — three verified scripts turn the mechanical half of a dsh upgrade into one command each: `scripts/bump-dsh.mjs <ver|latest|next>` (root pin + subpackage range anchors + verified list + lockfile), `scripts/gen-typert.mjs [upstream]` (the full in-repo Typert regeneration dance: vendor protocol source → tsconfig wiring → generator run → wiring fully reverted), and `scripts/re-vendor.mjs [upstream]` (byte-faithful client-ui source snapshot sync + exports entry-existence check). Semantic breaking seams remain human judgment — the leverage is continuous tracking: bump on every `next` rc instead of crossing two minors at once.
- **Migrated to `@deepseek-ai/dsh` 0.1.7-rc.2 (npm `next`)** — six breaking seams, all fixed in-repo (decision record: `docs/notes/architecture/2026-09-27-dsh-017-migration.zh.md`). Engine: `shell.run`→`execute().result()`; message sources become producer-declared kinds (`'tavern'` via `MessageSourceMap` augmentation). Client: sessions `open`/`list.current` → `retain()`/`retainedBy.<source>` (the tavern view holds its own `'tavern'` retain source). The regenerated Typert artifacts carry 0.1.7 strict codecs (`create()` factories). Agent presets are patch rows now (`@deepseek-ai/dsh-agent-preset`, `config.id`+`plugins`) — the profile-root directory format is gone. Two 0.1.7 session-format validations demanded engine changes: the tail-settlement signal appends a paired log-only `command/run` with a **unique** `tavern-tail-done-<seq>` commandId (consumers match the prefix), and the per-turn post shadowing defers to a microtask after `step/start` (a `system/message` before the step opens fails the format validator; appending inside the `step/start` observer hits the kernel's re-entry ban). `bin/dev.mjs bootstrap` no longer overwrites an existing profile `cordis.patch.yml` — that file is the user-override surface (e.g. the internal Anthropic baseURL). The mock LLM speaks the 0.1.7 wire: an Anthropic-protocol `/messages` SSE endpoint whose `event:` lines match the JSON `type`.
- **The tavern profile serves on its own port (3081)** — the bundle layer now overrides the `webserver` row, which the web-app layer defaults to 3080. `dsh web` and the tavern profile are two separate profiles that may well run at once, and sharing one port made the second one to start die on `EADDRINUSE`. `--port` still wins (an explicit flag reaches `ctx.webStartup.port`), so only the fallback moved. With that, `bin/dev.mjs` also forwards host arguments verbatim: it kept only arguments starting with `--`, which truncated value-taking flags (`--port 3099` arrived as a bare `--port`).
- Tail-agent write face rebuilt to mirror the stock dsh fs tools, fenced to `runtime/`: `runtimeEditor` (view/create/str_replace/insert) is retired for `runtimeWrite` (create or fully replace a document) and `runtimeEdit` (exact old_str→new_str replacement with `replace_all`); `runtimeRead` absorbs the view powers (cat -n numbering, optional `view_range`, two-level directory listings, 10k clip marker) and `insert` is dropped (multi-line `new_str` splices lines).
- The `runtime*` tools now participate in the kernel's parallel tool scheduling: the read pair and the write pair declare parallel-safe, with the write pair serializing same-path mutations through a per-path promise chain (different files write concurrently, one file's edits keep their model order); `runtimeDelete` and the card tools stay exclusive.
- `bin/dev.mjs` repo-root `.env` credential loading is now guarded by `.gitignore` (plus a committed `.env.example`).
- Docs reorganized into a system: `docs/` split into `architecture/` / `cards/` / `runtime/` / `testing/` / `release/` with a `docs/README.md` index; dated decision/debug records and the devlog moved to `docs/notes/`; all cross references updated. English editions land later as `foo.md` ↔ `foo.zh.md` pairs.
- Verified against `@deepseek-ai/dsh` 0.1.5-rc.2 (devDependency and compatibility list moved up from rc.1; full suite green on both).
- Legal hardening: README "Disclaimers" (not affiliated / card-content responsibility / as-is), explicit CC-BY 4.0 scoping (SRD corpus is not covered by the project MIT) and the CC-BY adaptation note in `THIRD_PARTY_NOTICES.md`.

### Fixed

- **Windows: every card was again dead on script execution — this time the sandbox refusal, not the quoting** — the kernel composes its shell executor per platform (`win32 → pwsh-sandbox`, whose sandbox backend is the Windows ACL restricted-token runner), and it refuses to run rather than fall back when the backend is unavailable. Engine-owned card spawns sent no sandbox policy, so the executor adopted the session's `workspace-write` surface and refused outright on such hosts: every card script died with `sandbox mode "workspace-write" is requested but no sandbox backend is usable on this host; refusing to run the command unconfined` — the galgame card as the familiar 「数据源未就绪」, dnd5e as `opening 落盘失败`. The added failure-visibility chain (Change above) was what let a real error message reach a user's screenshot and pin the refusal in minutes. Fixed by the explicit `trustedScriptPolicy` on the engine's shell seams (Change above); the v3 file-runner (Fixed below, 09-23) is unaffected and re-verified (note: `docs/notes/bug-fix/2026-09-27-windows-sandbox-refusal.zh.md`).
- **Windows: card scripts ran again — every one of them was exiting 1** — a card script reaches the host shell as a single command string, and the v2 face inlined its decoder into that string (`node -e '<decoder>' -- <b64 script> <b64 args>`). That holds on POSIX and on pwsh ≥ 7.3, but dsh's last-resort Windows executor is Windows PowerShell 5.1, which re-serializes native arguments Legacy-style and strips the decoder's embedded double quotes: node compiled a mangled `-e` and every card script exited 1, showing on the model face as silent failure and on screen only where a card pumps data purely client-side (dnd5e's `hud-left`). The runner is now a file — `packages/engine/runner/runner.cjs`, shipped through the engine's `files` — invoked as `node <runner> <b64 script path> <b64 args>`: the one quoted token left is a path, and `"` is an illegal Windows filename character, so no PowerShell generation can strip it. Scripts are imported by real path, so relative imports inside a card script resolve naturally, and base64 now carries only the args payload. The stdout-draining exit hardening moved into the runner unchanged.
- **Windows: deleting a session failed with `EPERM`** — `deleteSession` cancelled with `stop()` and then removed the workspace and log directories synchronously, but cancellation is advisory: the cancelled agents release their file handles on later ticks. POSIX hides that race (unlink succeeds on an open file); Windows refuses it (`EPERM`/`EACCES`). The rm now runs behind a bounded 12 × 250 ms backoff covering that denial family, and a workspace that still cannot be removed keeps its binding, so the player can simply retry. The session-log project directory is not load-bearing — the boot-time orphan sweep collects it — so a residual lock there degrades to a warning rather than failing the round. `deleteSession` is async now and its Remote owner awaits it; the previous fire-and-forget shape swallowed engine failures as unhandled rejections and reported success.
- **`pnpm bootstrap` no longer wedges when the profile lockfile lags the generated manifest** — bootstrap rewrites the profile `package.json` on every run (absolute `link:` paths to the invoking checkout, host packages pinned to the newest verified version) but left the profile's `pnpm-lock.yaml` untouched, and the forced `CI: 'true'` made pnpm default to frozen-lockfile; any change to that manifest — a second checkout at a different path, a verified-host bump rc.1→rc.2 — then failed outright with `ERR_PNPM_OUTDATED_LOCKFILE` until the lockfile was removed by hand. `bin/dev.mjs` now keeps a generation stamp (`.bootstrap-generation.json`) next to the lockfile: the frozen headless path is taken only when the stamped dependency set still matches the freshly generated one; otherwise the stale lockfile is dropped and a single unfrozen install re-resolves and re-stamps. A frozen run that still fails (hand-edited or half-written lockfile) falls back the same way once. The unfreeze override goes through both pnpm env channels (`pnpm_config_*` for pnpm ≥11, `npm_config_*` for ≤10 — neither release reads the other's spelling).
- **Windows: save directory names no longer embed `:`** — `readableSaveName` produced a colon-separated wall clock (`autosave-2026-09-14-01:22:28`), and `:` is illegal inside a Windows path segment, so `writeSave`'s `mkdirSync` failed with `ENOENT`: autosave broke outright, and 16 engine composition tests failed with it. Every field is dash-separated now (`autosave-2026-09-14-01-22-28`). Existing saves are unaffected — rows are listed by directory entry and ordered by mtime, and the name is only ever tested for the `autosave-` prefix, never parsed. The READMEs' examples were updated to match; both already documented a pure-dash format, which the code now actually produces.
- **Windows: copying into a non-ASCII destination no longer silently drops every file** — the engine used `fs.cpSync(..., { recursive: true })`, which on Windows copies *nothing* into a destination path carrying non-ASCII characters and reports no error at all. Since the destination is routinely user text, this hit publishing a card whose title is non-ASCII (library entry left with an empty `preset/`), manual saves with non-ASCII names (empty snapshot), and editor copies/moves to non-ASCII paths. All copy sites now go through a hand-rolled `copyTree` / `copyPath` pair built on `readdirSync` / `copyFileSync`, which handle the same paths correctly (verified on Node 24.14.0; equivalent on POSIX).
- **`pnpm build` and `pnpm typecheck` work again** — dropped `--config-loader tsx` from all seven `tsdown` invocations (root `build:lib:host` / `build:lib:client` / `typecheck`; `packages/api` and `packages/ui` `bundle` / `watch`). tsx's CJS loader hook resolved `node:fs?tsx-namespace=…` as a file path and died with `ENOENT`, so the host face never built. The flag was never needed: tsdown loads `tsdown.config.ts` natively, and upstream dsh's own `build:lib:*` scripts carry no such flag.
- **A fresh checkout builds again (CI was red on every platform)** — `packages/api/src/client/index.ts` mounts the browser Remote stub through the bare import `dsh-tavern-fengyue-api/remote`, which `exports["./remote"]` resolves to `lib/typert.remote-client.d.ts`; the client face's `tsc -b` therefore needs the four generated Typert artifacts present. They are produced by `@deepseek-ai/dsh-typert-generator`, and this repo cannot run that generator: it recognises `@Remote` only when the protocol's declarations belong to a project of the analyzed workspace, while here `@deepseek-ai/dsh-typert-protocol` is a published `node_modules` dependency (`isTypeMetaSymbol` / `registrationForFile` in the generator's `analyzer.js`). Nothing generated them here, so they existed only as a hand-carried snapshot which the blanket `lib/` ignore rule kept out of git — a fresh clone failed with `TS2307: Cannot find module 'dsh-tavern-fengyue-api/remote'` and never reached the tests. They are now versioned via four `.gitignore` exceptions (`packages/api/lib/typert.*`); every other `lib/` artifact stays ignored. The rationale and the regeneration procedure live in `packages/api/REGENERATE.md`.
- dnd5e `cast` tool: attack-type spells now apply the parsed damage-modifier chain (immunity → 0, resistance → half, vulnerability → ×2), matching the `attack` tool; removed a dead save-branch no-op.

### Removed

- `fixtures/` — a nine-file stub card (`fixtures/cards/card/preset/…`, 2.1 KB) with no remaining consumer: no code, test, config, or live doc references the path, and the two scripts it carried (`get_state.mjs`, `roll.mjs`) exist only there. The example cards that ARE exercised live under `tavern_presets/` (`dnd`, `dnd5e`, `芙宁娜`).
- `scripts/llm-debug.sh` — pre-extraction leftover referencing a no-longer-shipped proxy script; the mock-LLM dev flow (`scripts/mock-llm.mjs`) covers keyless debugging.
